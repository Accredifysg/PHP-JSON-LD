# Cross-implementation interop corpus

Realistic VC 2.0 / OBv3 documents whose RDF output is compared against
goldens generated by **jsonld.js** with RDFC-1.0 canonicalization — the exact
quad set an `eddsa-rdfc-2022` proof is computed over.

## Why this exists (in addition to the W3C suite)

A processor that mis-expands a document *consistently* passes every internal
round-trip: signer and verifier recompute the same wrong quads, and the bug
only surfaces when a conformant external implementation rejects the
signature. That is exactly how the PR #38 bug (type-scoped context lookup
ignoring the active context) shipped: the W3C suite contains **no** fixture
where an embedded node `@context` defines a type-scoped context, so 1287
green conformance tests said nothing about the VC-in-VP shape. This corpus
pins the reference implementation's output for the shapes we actually sign.

## Layout

- `fixtures/cases/<name>/input.jsonld` — the document.
- `fixtures/cases/<name>/expected.nq` — golden canonical N-Quads from jsonld.js. Never hand-edit.
- `fixtures/cases/<name>/case.json` — optional generator config (`safe: false` needs a `note` explaining the intended loss).
- `fixtures/contexts/` — vendored remote contexts + `index.json` (URL → file). Both the PHP loader and the golden generator resolve contexts **only** from here; any other URL errors, so the corpus is offline-deterministic.
- `fixtures/goldens.json` — generator/version manifest, written by regeneration.

## Cases

| case | exercises |
| --- | --- |
| `embedded-node-type-scoped-context` | Minimal PR #38 shape: nested node's own `@context` defines a type carrying a scoped context. |
| `minimal-vc-v2` | VC 2.0 credential; subject claims live in a type-scoped context (`Individual`). |
| `vp-embedded-vc-scoped-claims` | The incident shape: VP whose embedded credentials carry their own `@context`; claims under type-scoped `Individual` / `CorporateEntity`; `@container:@graph` blank-node graphs. |
| `obv3-achievement` | Open Badges v3 achievement credential over the real 1EdTech context. |
| `vc-context-null-isolation` | VC 2.0 `verifiableCredential` `@context:null` isolation: a presentation-level type-scoped context must NOT leak into the embedded credential (regression guard for the `documentBase`-fallback removal in `Expansion::activateTypeScopedContexts()`). |
| `vc1-ed25519-2020-protected-proof` | VCDM 1.1 credential over the published VC 1.x + ed25519-2020/v1 contexts — the standard `Ed25519Signature2020` stack. VC1's type-scoped `proof` is spelled `sec:proof` while the suite context protects `proof` under the absolute IRI; protected-redefinition identity must be judged over EXPANDED definitions (§4.2.2) or the stack falsely fails. |

## Regenerating goldens

```sh
./tests/Interop/regenerate.sh   # docker; pins node:22 + jsonld@8
```

Goldens change only when a fixture changes or the reference implementation
fixes a bug — review any golden diff like a code change. Blank-node labels
differ between RDFC-1.0 (`_:c14n0`) and this processor (`_:b0`); the test
compares datasets up to blank-node isomorphism, so labels are irrelevant but
any missing, extra, or altered quad fails.

## Vendored context sources

- `credentials-v2.jsonld` — <https://www.w3.org/ns/credentials/v2> (W3C)
- `ob-v3p0-3.0.3.jsonld` — <https://purl.imsglobal.org/spec/ob/v3p0/context-3.0.3.json> (1EdTech)
- `example-individual-v1.jsonld` — invented for the corpus; models an issuer context whose subject types (`Individual`, `CorporateEntity`) carry type-scoped claim terms, mirroring the incident's credential shape. All personal data in fixtures is fabricated.
